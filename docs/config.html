Configuration and files

Tracked configuration lives in this repository. Everything operational - state, credentials, sessions, the project registry - stays outside it.

Parsing and version comparison for the stack manifest live in one place, firstmate/fm-stack-manifest.sh. Captain harness selection and availability live in firstmate/fm-captain-lib.sh. Extend those instead of adding a second parser or detector.

Machine-local files

Nothing below is tracked. The installer creates what it owns; the rest belongs to FirstMate or to you.

PathWhat it is
~/.config/firstmate-config/envResolved paths, written by install.sh. Never commit it.
$FM_HOME/state/Runtime and task state. Includes .fm-launch, the record of how the Captain was started, and bots.check.sh once fm bot check-install has run.
$FM_HOME/data/Captain preferences (captain.md), the project registry (projects.md), board data under board/, and bot specs under bots/ (with their filed markers in bots/.filed/).
$FM_HOME/config/backendThe runtime backend; the installer sets it to herdr.
$FM_HOME/config/crew-dispatch.jsonSymlink to the tracked routing file.
$FM_HOME/projects/The projects/<name> shorthand location for project checkouts, used by FirstMate's spawn script.
~/.agents/skills/Symlinks to shared skills.
~/.agents/commands/Symlinks to this repository's slash commands.
~/.omp/agent/agents/fm-*.mdSymlinks to the role files, one OMP agent per role. Other files there are yours and are left alone.
~/.agents/referencesSymlink to the addyosmani references that its skills link to.
~/.local/share/firstmate-config/skills-src/Cache with one clone per pinned skill repository.
~/.local/bin/fm, ~/.local/bin/ponytail-updateLauncher symlinks.
~/.pi/agent/git/github.com/DietrichGebert/ponytailPi's own pinned Ponytail checkout, kept separate from the shared skill cache.

$FM_HOME must not be a secondmate home. The installer and the launcher both refuse a directory carrying the .fm-secondmate-home marker.

The env file wins

The launcher sources the env file first, and the file assigns FIRSTMATE_ROOT, FM_HOME, and FM_BACKEND unconditionally. A value you exported in your shell is therefore overridden by the file. To use different paths for one run, point FM_CONFIG_ENV at another file.

The env file

# Written by firstmate-config/install.sh. Machine-local: never commit this.
FIRSTMATE_ROOT="/path/to/firstmate"
FM_CONFIG_ROOT="/path/to/firstmate-config"
FM_HOME="/path/to/.firstmate"
FM_BACKEND="herdr"
export FIRSTMATE_ROOT FM_CONFIG_ROOT FM_HOME FM_BACKEND

If its content differs from what the installer would write, install.sh --verify reports DRIFT and install.sh rewrites it.

stack-manifest.tsv

Tab-separated key and value. It is the single source for stack compatibility, and nothing else should hardcode these values.

KeyMeaning
schema_versionManifest format version.
firstmate_repoThe only origin URL fm update accepts for the official checkout.
firstmate_validated_commitFull hash of the FirstMate commit this configuration was validated against.
pi_min_version, pi_tested_versionPi hard minimum and tested version.
omp_min_version, omp_tested_versionOMP hard minimum and tested version.
herdr_min_version, herdr_tested_versionHerdr hard minimum and tested version.

Below the minimum is a FAIL; above the tested version is a WARNING. Auth, credentials, machine paths, the project registry, runtime task state, and Captain model routing are deliberately not in this file. To move a pin, verify the new values against a real installation, edit the file, and commit.

captain-startup-models.tsv

Tab-separated model, effort, and an optional harness (omp, pi, or blank for both). Blank lines and lines starting with # are ignored. Order is preference. The behavior is described on Architecture and startup.

skills/external.lock

Tab-separated our-id, repo, commit, path-in-repo, and installed-skill-name. Always a full commit, never a branch. See Roles and skills.
