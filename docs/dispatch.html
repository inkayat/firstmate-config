Dispatch routing

Every delegated task maps to one dispatch category by what the work is, not by how big it looks. The category selects the worker's harness, model, and effort. firstmate/crew-dispatch.json is the source of truth.

Five separate decisions

The Captain keeps these apart so that one never drags the others along. A hard task does not automatically mean the strongest model, and a strong model does not automatically mean maximum effort.

DecisionChosen by
CategorySemantic fit, read from each rule's when text.
Harness, model, effortThe matched rule's use candidate.
Rolesenior-fullstack by default; architecture and tenth-man only for their matching categories.
SkillsSelected per task; see Roles and skills.
Scout or shipJudged per task. EXPLORE, RESEARCH, REVIEW, ARCHITECTURE, and TENTH-MAN are usually read-only; the rest usually mutate. Neither mapping is fixed.

An explicit choice from you always wins over the table. The trace line then says captain override.

Routing philosophy

  • Substantive work goes to Opus 5.5. That means meaningful new behavior, a nontrivial refactor, multi-component work, or real cross-component regression risk. When unsure between Sonnet 5.5 and Opus 5.5 for substantive work, choose Opus 5.5.
  • Bounded work may stay on Sonnet 5.5, and trivial work on Haiku 4.5 or GPT-6 Luna.
  • GPT-6.1 Sol is the everyday cross-family route: RESEARCH's Pi-tooling rule, REVIEW's second reviewer, TENTH-MAN's default for Claude-authored work, and DEEP's escalations.
  • GPT-6 Astra is confined to Pi and to each category's narrowest escalation: ARCHITECTURE's ultra-exceptional rule, DEEP's last escalation, and TENTH-MAN's critical case.
  • TENTH-MAN enforces model-family diversity. It never shares a family with the work it challenges.
  • Effort is not negotiable downward. Where the table says xhigh and the lane cannot run xhigh, the task is reported blocked and waits for a decision; it does not run at reduced effort.
  • Provider availability and capacity break ties inside a rule's own candidates. They never override the category or the rule.

Sonnet 5, Opus 5, Fable 5.1, GPT-5.5, GPT-5.6 Luna and Sol, and GPT-6 Sol are retired from worker routing. The local Qwen/Ollama lane is intentionally absent; fm doctor reports it as DEFERRED.

Reading a rule

crew-dispatch.json has two top-level keys, rules (a list) and default. Each rule has exactly category, when, use, and why:

{
  "rules": [
    {
      "category": "IMPLEMENT",
      "when": "natural-language test for when this rule applies",
      "use": [
        { "harness": "omp", "model": "anthropic/claude-sonnet-5-5", "effort": "high" }
      ],
      "why": "why this route fits"
    }
  ],
  "default": [
    { "harness": "omp", "model": "anthropic/claude-opus-5-5", "effort": "high" }
  ]
}
  • default is a bare candidate list used when no rule matches.
  • Several rules can share one category. The extra ones are sub-lanes with a narrower trigger. The Captain shows the matched rule as #n, its 1-based position within its category.
  • A use array is resolved by FirstMate's quota procedure, so it contains only genuine peers. Only QUICK and simple EXPLORE pair two models (Haiku and Luna). Every other rule has one candidate, so nothing can be picked by quota ahead of an Opus 5.5 primary.
  • Each primary rule's when text names the neighboring category it could be confused with and states the test that separates them (for example QUICK against IMPLEMENT, or REVIEW against TENTH-MAN). Read those before changing a category.

Change the routing

install.sh links this file into $FM_HOME/config/crew-dispatch.json, which is the path FirstMate reads, so editing the tracked file edits the live routing source. Validate afterwards:

fm doctor | grep -E 'routing\.'

routing.crew_dispatch_valid checks the file's structure, and a routing.model.<harness>.<model> line per route reports whether that model and effort resolve under that harness.

Sub-lanes are added as separate same-category rules, never as new categories. tests/routing-taxonomy.sh pins the exact candidate tuples, so a route change is a deliberate edit to the JSON and that test, with firstmate/primary-policy.md kept aligned.
