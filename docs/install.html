Installation and first run

One clone, one idempotent script. Running ./install.sh again is the normal way to reconcile a machine, not a special case.

Requirements

The installer checks the toolchain first and stops before changing anything if a required tool is missing.

ToolStatusWhy
gitrequiredClones, fast-forwards, and pins everything.
omprequiredDefault Captain harness and the harness for most workers.
pirequiredExplicit Captain fallback and the harness for Pi-routed workers.
herdrrequiredThe runtime backend. The launcher also refuses to start without it while FM_BACKEND=herdr.
jq, treehouse, gh, bunrecommendedMissing tools only print a warn line; they are needed for full fleet behavior.
python3conditionalNeeded only to reconcile Pi's Ponytail package settings (step 9).

Minimum and tested versions of Pi, OMP, and Herdr live in firstmate/stack-manifest.tsv. fm doctor compares your installed versions with it; a newer tool is a WARNING, a tool below the minimum is a FAIL.

Install

git clone https://github.com/inkayat/firstmate-config.git
cd firstmate-config
./install.sh
Run it from the clone you intend to keep

The installer points fm, the dispatch file, and the skill, command, and role-agent links at the checkout it runs from. Do not run it from a throwaway worktree.

It works through nine numbered steps. Every step states a desired end state and changes only what differs:

  1. Toolchain - the checks above.
  2. Official FirstMate checkout - cloned to FIRSTMATE_ROOT and pinned to the validated commit only if it is missing. An existing checkout is reported against the baseline (ok, or a warn if ahead, behind, or diverged) and never modified.
  3. Operational home - creates state, data, config, and projects under FM_HOME.
  4. Environment file - writes ~/.config/firstmate-config/env with the resolved paths.
  5. Runtime backend - sets $FM_HOME/config/backend to herdr.
  6. Dispatch and Captain file - symlinks crew-dispatch.json into $FM_HOME/config/ and seeds $FM_HOME/data/captain.md once; an existing copy is never overwritten.
  7. Global skills, commands, role agents, and team policy - links this repository's skills and the pinned external skills into ~/.agents/skills, its slash commands (commands/*.md, such as /bots) into ~/.agents/commands, each role file into ~/.omp/agent/agents/fm-<role>.md, and the team policy extension into ~/.omp/agent/extensions/fm-team-policy.ts. A file or directory already at a link path is reported and left alone; so is a role-agent or extension symlink that does not point at a firstmate-config file.
  8. Launchers - links fm and ponytail-update into ~/.local/bin and warns if that directory is not on PATH.
  9. Pi Ponytail package - a separate pinned checkout for Pi, with a skills filter so its bundled duplicates never shadow the shared ones.

A trimmed run on a settled machine looks like this:

1. toolchain
  ok      git present
  ok      omp present
  ...
2. official FirstMate checkout
  ok      present at ~/Developer/tools/firstmate
  ok      matches the validated baseline commit 
...
7. global skills, commands, role agents, and team policy
  ok      ~/.agents/skills/systematic-debugging
  ok      ~/.agents/commands/bots.md
  ok      ~/.omp/agent/agents/fm-senior-fullstack.md
  ok      ~/.omp/agent/extensions/fm-team-policy.ts
  ...
8. command launchers
  ok      ~/.local/bin is on PATH

install: 0 change(s), 0 failure(s)

Lines are prefixed ok, changed, warn, DRIFT (only with --verify), or FAIL. A FAIL makes the script exit nonzero.

Verify

./install.sh --verify   # read-only drift check
fm version              # compact identity of the installed stack
fm doctor               # read-only diagnostics

--verify changes nothing and ends with verify: N drift item(s), M failure(s). A clean machine reports verify: 0 drift item(s), 0 failure(s).

fm doctor exits 0 when the mandatory architecture is healthy - warnings do not change that - and 1 on a genuine break such as a missing Captain executable, an unreachable Herdr server, or another fm earlier on your PATH. See the CLI reference for the full list.

First run

Preview what the launcher will do without starting anything:

fm --check
CONFIG_ROOT=~/src/firstmate-config
FIRSTMATE_ROOT=~/Developer/tools/firstmate
FM_HOME=~/.firstmate
FM_BACKEND=herdr
FM_FORK_ORIGIN_CWD=~/src/my-project
FM_FORK_ORIGIN_IS_PROJECT=true
CAPTAIN_HARNESS=omp
CAPTAIN_CWD=~/Developer/tools/firstmate
CAPTAIN_BIN=omp
CAPTAIN_EXTENSIONS=discover
PREFERRED_MODEL=openai-codex/gpt-6.1-sol
PREFERRED_EFFORT=medium
SELECTED_MODEL=openai-codex/gpt-6.1-sol
SELECTED_EFFORT=medium
SELECTED_AVAILABILITY=AVAILABLE
...
PREFLIGHT=ok

Three fields matter on a first run:

  • SELECTED_MODEL - the first startup candidate that is not known to be unavailable. If it differs from PREFERRED_MODEL, a FALLBACK_REASON line says why.
  • CAPTAIN_CWD - always the official FirstMate checkout, wherever you ran fm from.
  • FM_FORK_ORIGIN_IS_PROJECT - whether your launch directory is a Git project. It is used only as a default-project hint.

fm --print-command prints the same resolution plus the exact harness command line. Then start the Captain:

cd ~/src/my-project   # optional: becomes the default-project hint
fm

The launcher prints the harness, the preferred and selected model, and availability, then replaces itself with the harness process.

To use the Pi fallback instead, pass the harness before any subcommand: fm --harness pi. It is explicit and never automatic.

Projects

Project registration and the task lifecycle belong to upstream FirstMate. This configuration only reads them: a task's project is resolved by an explicit path or name, then FirstMate's registry (data/projects.md), then your launch directory as a hint. The full order is on Architecture and startup. Nothing about a project is copied into this repository.

What the installer never does

  • Store a credential.
  • Touch a project repository.
  • Modify the official FirstMate checkout after it exists.
  • Overwrite a file at a link location that it does not own - it prints warn ... leaving it alone instead.
  • Create or activate a bot - specs and the watcher check exist only after fm bot create and fm bot check-install.

There is no uninstall command. Removing the symlinks the installer created and the files it wrote (listed on Configuration and files) is a manual step.
