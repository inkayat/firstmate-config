Task board

fm board shows live FirstMate work as a Kanban board. It is a deterministic projection of FirstMate's own records, not a second task database: nothing on the board is decided by a model, and no daemon runs behind it.

Open it

fm board            # terminal-browser viewer
fm board --lavish   # the same static page through Lavish

Each open refreshes the data first. While the viewer it launched is running, fm board keeps re-rendering, and the page re-reads its data file every few seconds, so a status change appears without a manual reload. The selected tab is preserved.

Columns

Columns come from FirstMate's structured state fields only, never from the prose of a hold or note.

ColumnContains
todo TodoQueued or deferred work: plain queued rows, dated or aged Captain deferrals, and non-Captain holds.
in_progress In ProgressA live child that is working.
waiting_review Waiting ReviewA finished worker awaiting review or landing, a gate or needs-decision that is parked, or a live Captain call.
blocked BlockedAn unresolved dependency, or a child that is blocked, paused, failed, or unknown.
done CompletedOnly a landed backlog row.

A finished worker is therefore Waiting Review, not Completed, until its work has landed.

Task details

Every card has a keyboard-reachable Details link (board.html#task/<id>) to that task's own view in the same page. Back to board or Escape returns to the board with focus on the card.

At render time one lookup per FirstMate task adds its body, notes, status and hold, dependencies, review context, worker summary, and links to the page's data file. A field its source reports as unset reads None; a field no source has reads as not available. Raw .meta and .status content is never shown.

Data files

FileRole
$FM_HOME/data/board/state.jsonCurrent board state with stable task ids. Never regenerated from scratch.
$FM_HOME/data/board/events.jsonlAppend-only debugging history. Rendering never replays it, and an unchanged projection is neither rewritten nor logged.
$FM_HOME/data/board/board-data.jsGenerated data the static page reads.

FirstMate's backlog and execution records (data/backlog.md, state/home-summary.json) stay authoritative. Cards for finished FirstMate work are retired when FirstMate stops publishing them, but only when its summary surfaces are provably complete. Cards you added by hand are never retired.

fm-board commands

The board script has more subcommands than fm board exposes. fm board [--lavish] runs fm-board open. The script lives in the firstmate-config checkout at bin/fm-board and is not linked onto PATH by the installer, so call it by path.

bin/fm-board list --state blocked
bin/fm-board show <id> --json
bin/fm-board summary
bin/fm-board add --project my-project --title "Check release notes" --id notes-1
bin/fm-board move notes-1 in_progress
SubcommandOptions
list--project, --state, --json
show<id>, --json
summary--project, --json; counts per state
add--project, --title, and --id required; --agent, --note optional. New cards start in todo.
update<id> with --project, --title, --agent, --note
move<id> <state>, where state is one of todo, in_progress, waiting_review, blocked, done
renderRegenerate the page data without opening a viewer.
open--lavish

Task ids are explicit and never generated: lowercase letters, digits, and hyphens, starting with a letter or digit. Cards added with add are manual rows, never retired by a reconcile.
