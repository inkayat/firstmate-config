# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- `README.md` is the project-level source of truth: layout, install, the multi-project Captain model, and routing. Read it first.
- The Captain's project-selection precedence ("which project", the launch-directory hint, and why a project's instructions/skills are never preloaded at startup) is owned by `firstmate/primary-policy.md` section 1; do not duplicate it here.
- The delegated-worker context/skill-class contract (why Pi and OMP need an explicit compact handoff instead of "the harness discovers project instructions natively", the three skill populations - official FirstMate internal, firstmate-config shared worker, project-local - and the required per-task path/precedence handoff) is owned by `firstmate/primary-policy.md` section 2 and README.md "Worker context and skill classes"; do not duplicate it here.
- Tests: `tests/smoke.sh` (launcher/install/herdr), `tests/model-selection.sh` (captain startup model chain), `tests/multi-project-captain.sh` (project resolution, real `bin/fm-spawn.sh` dispatch/isolation, instruction/skill separation, Pi/OMP routing - requires `tmux` and `treehouse` on `PATH`, uses an isolated `TMUX_TMPDIR` server so it never touches the shared/live session), `tests/doctor.sh` (`fm doctor` statuses/exit codes/JSON schema, fully fixture-isolated - see `tests/doctor.sh`'s own header for why its fixture PATH is hermetic rather than `$PATH`-appended), `tests/stack-manifest.sh` (`firstmate/stack-manifest.tsv` compatibility: unit tests of `firstmate/fm-stack-manifest.sh`'s parser/comparator plus fixture-isolated `install.sh`/`fm-doctor`/`fm version` end-to-end scenarios, offline via local Git origins - never the network), `tests/worker-context.sh` (delegated-worker context/skill-class handoff: offline fixture plus a real zero-inference probe of Pi's installed native resource loader - pre-implementation evidence only, never a substitute for a live delegated Pi/OMP fixture run).
- `firstmate/stack-manifest.tsv` is the single tracked source of truth for stack compatibility (official FirstMate repo/validated commit, Pi/OMP/Herdr min/tested versions - see README.md "Stack compatibility" and the manifest's own header comment for what is deliberately excluded). `firstmate/fm-stack-manifest.sh` is the one parsing/comparison owner, sourced by `install.sh`, `bin/fm-doctor`, and `bin/fm-version`; never duplicate its TSV parsing or version comparison in a script or a test - fixtures may generate alternate manifests, but assertions against the real tracked manifest must load it dynamically (`stack_manifest_load`), never hardcode its values as separate literals.
- `data/projects.md`/`bin/fm-project-mode.sh` is a registered-**delivery-posture** lookup only, never a project resolver or location lookup (its own header, AGENTS.md section 7). Project name -> path resolution is `bin/fm-spawn.sh`'s own `projects/<name>` shorthand against `$FM_HOME/projects/<name>` - the one mechanism upstream provides; do not add a second one.
- `firstmate/fm-captain-lib.sh` is the one authoritative Captain model-availability path (`model_availability` and its helpers), sourced by both `bin/fm` (startup selection) and `bin/fm-doctor` (`fm doctor` reporting). Never fork this logic between the two; extend the shared lib instead. `fm doctor`/`fm doctor --json` (README.md "fm doctor") is read-only and never mutates `FM_HOME`, a project, or routing - see its own header comment for the exact mandatory-vs-advisory exit-code gate.
- Bounded internal helpers remain supported by `firstmate/primary-policy.md` section 6: FirstMate owns macro orchestration; OMP's native `task` tool owns bounded task-local delegation. Pi has no bundled equivalent and stays not-applicable. `tests/worker-context.sh` provides `internal-prepare`/`internal-handoff` canaries inside the parent's worktree and `validate` report checks; corroborate reports with existing harness session evidence, not new telemetry. These checks do not enforce tool ordering or gate FirstMate completion; see README.md "Worker context and skill classes" and "Completion evidence limits".
- A checkpoint/ordering-gate experiment for target-discovery and a verification-provenance classifier were tried, then fully removed (see git history around "Remove abandoned provenance and checkpoint enforcement experiment"). `tests/worker-context.sh`'s `scope-prepare`/`scope-handoff`/`scope-validate` restore only the useful open-ended-discovery coverage from that removal (root-only launch scope, an independently selected nested candidate, body-only canary evidence that its instruction/skill were applied) - never read-order, tool-order, or completion-gate checks. Do not reintroduce that machinery.
- Adding or changing anything under `skills/*/SKILL.md` from a disposable task worktree makes `tests/smoke.sh`'s "every configured global skill is installed" check fail, for the same structural reason `install.sh` reports drift there: a worktree cannot symlink into the machine's shared `~/.agents/skills`. Expected there, not a regression - a real reconcile requires `./install.sh` (no `--verify`) from the primary checkout, never from a task worktree.
- `./install.sh --verify` is read-only and safe from a disposable worktree. Plain `./install.sh` (no `--verify`) repoints the *live machine's* symlinks (`~/.local/bin/fm`, `~/.agents/skills/*`, `~/.firstmate/config/crew-dispatch.json`) at whatever checkout you run it from - never run it from a task worktree, only from the machine's primary checkout. Because of this, `tests/smoke.sh` run from a worktree will always report installer drift against the primary checkout's path; that failure is expected there and is not a regression. Its live-captain `fm_pi_extension_owns_supervision` check reads the actual running session's extension-load state and can flip pass/fail between two runs seconds apart with no code change; treat it as live-session timing, not a regression, unless it is reproducibly false.
